# DES-003 会社情報ページ 設計

## 方針
- **ToDo サイトとは独立した、静的な 1 ページ**を `site/lp/` に追加する。ToDo の `index.html` `app.js` `todo.js` `style.css` は変更しない。
- **JavaScript を使わない**（HTML と CSS だけ）。ページ内のリンクは `<a href="#…">`、スムーズスクロールは CSS の `scroll-behavior` で行う。理由は、外部依存とビルドを持たない（NFR-001）ことと、動きをブラウザの標準に任せて、確認すべき範囲を減らすため。
- **構成だけを参考にし、内容・配色・意匠は独自**にする（REQ-003 のスコープ外、NFR-008）。文言はすべて下の「文言の案」のダミーを使い、参照元の文章を写さない。
- **貼られた前提の適用範囲**: 「`todo.js` は純粋関数だけ、`app.js` は DOM と保存だけ」「`dueDate` を持たせる」は ToDo のための前提で、このページには対応する構成要素がないので適用しない。「外部ライブラリを使わない（NFR-001）」は適用する。

- 既存の静的テストは `site/` 直下のファイルだけを見ているので、`site/lp/` は対象外になっている。追加のテストで補う。

## データとインターフェース
JavaScript もデータ保存もない。ページの「契約」は、次の id・見出し・文言になる。

### 文書の構造
```
<html lang="ja">
  <header>  小見出し COMPANY / <h1>会社情報</h1> / <nav aria-label="ページ内ナビゲーション"> 5 つのリンク
  <main>    <section id="mission"> <section id="vision"> <section id="founder"> <section id="outline"> <section id="deck">
  <footer>  デモの注記
```
- 各 `section` は `aria-labelledby` で自分の `<h2>` を指す。見出しの階層は、`<h1>` が 1 つ、`<h2>` が 5 つ。
- ナビゲーションのリンクは、表示名と移動先が次のとおり。

| 表示名 | `href` | 移動先の `section` |
|---|---|---|
| MISSION | `#mission` | `id="mission"` |
| VISION | `#vision` | `id="vision"` |
| FOUNDER | `#founder` | `id="founder"` |
| OUTLINE | `#outline` | `id="outline"` |
| COMPANY DECK | `#deck` | `id="deck"` |

- OUTLINE は定義リスト（`<dl>` の `<dt>` が項目名、`<dd>` が内容）にする。所在地と海外拠点は、1 つの `<dd>` の中に、拠点ごとの行を並べる。

## 画面・振る舞い
- **見出し領域**: 全幅の帯。背景は濃い緑（`--band`）、文字は白（`--band-ink`）。小見出しは小さく、ページ名は大きく。その下にナビゲーションを置く。
- **ナビゲーション**: 5 つのリンクを横に並べ、幅が足りなければ折り返す。各リンクの高さは 44px 以上。押すと、該当のセクションへ移動する。`scroll-behavior: smooth` を指定するが、`prefers-reduced-motion: reduce` のときは無効にする。
- **本文**: 最大幅 960px で中央に寄せ、セクションを縦に並べる。各セクションは、小見出し、見出し、本文の順。FOUNDER と COMPANY DECK は、白い面（`--card`）に載せる。
- **OUTLINE の一覧**: 幅 720px 以上では、項目名（固定幅）と内容を 2 列に、720px 未満では、項目名の下に内容を縦に並べる。長い住所は折り返す。
- **COMPANY DECK**: ボタンにしない。押せそうに見えて何も起きない部品を作らないため。準備中の旨を本文で示す。
- **フッター**: 注記を、通常の本文より小さくならない大きさで表示する。
- **フォーカス**: `:focus-visible` で 3px のアウトラインを出す。見出し領域の中では、アウトラインの色を白にする（濃い緑の背景では、青のアウトラインが見えにくいため）。
- **配色**（案。実装時に、下のコントラストの組を確かめる）:

| 変数 | 値 | 用途 |
|---|---|---|
| `--bg` | `#f4f7f6` | ページの背景 |
| `--card` | `#ffffff` | 面の背景 |
| `--ink` | `#1d2b2a` | 本文・見出しの文字 |
| `--muted` | `#4b5f5d` | 小見出し・補足の文字 |
| `--band` | `#1f5f5b` | 見出し領域の背景 |
| `--band-ink` | `#ffffff` | 見出し領域の文字 |
| `--line` | `#d5dedc` | 区切り線 |
| `--focus` | `#0b57d0` | フォーカスのアウトライン |

- ダークモードには対応しない（`color-scheme: light`）。

## 設計判断（要件に書かれていないこと）
- ページの置き場所は `site/lp/`。`site/**` は Codex の編集範囲に含まれるので、新しい最上位のフォルダを作らずに済む。
- JavaScript を使わない。「代表メッセージ」の開閉のような動きは、REQ-003 のスコープ外。
- 参照元の「Google map」のリンクは載せない。外部 URL に依存せず、NFR-001 の静的テストをそのまま保てるため。
- 参照元の配色と「+」の意匠は使わない。ダミーの文言と独自の配色にして、転載にならないようにする。
- 画像ファイルは使わない。必要な装飾は CSS だけで作る。
- 電話・許認可の欄は、番号の形をした架空の値を作らず、`03-0000-0000` や「なし（ダミー）」にする。実在の番号と取り違えられないようにするため。
- 既存の ToDo サイトから、このページへのリンクは張らない。

## テスト計画
### 自動（`npm test`。実装時に追加する）
すべて `static.test.mjs` に追加し、`site/lp/` のファイルを読む。失敗メッセージは、何が違反で、どこをどう直すかを書く。
- `[FR-011]` `index.html` に、`COMPANY` の小見出しと `<h1>会社情報</h1>` がある。
- `[FR-012]` `<nav>` に 5 つのリンク（MISSION・VISION・FOUNDER・OUTLINE・COMPANY DECK）があり、各 `href` が、同じファイル内の存在する `id` を指す。CSS に `scroll-behavior` と `prefers-reduced-motion` の指定がある。
- `[FR-013]` `[FR-014]` `[FR-015]` `[FR-017]` 該当する `section` が、`aria-labelledby` が指す `<h2>` と、本文を持つ（FOUNDER は役職・氏名・経歴、COMPANY DECK は「準備中」の文字を含む）。
- `[FR-016]` `section#outline` の `<dt>` が、9 項目（会社名・代表・資本金・所在地・海外拠点・電話・従業員数・主要取引銀行・許認可・届出）をこの順で持ち、各 `<dt>` に `<dd>` が続く。
- `[FR-018]` `<footer>` に、「デモ」と「架空」の文字を含む注記がある。
- `[NFR-001]` `site/lp/` の `.html` と `.css` に、外部 URL がない。`index.html` が読み込むのは相対パスの `style.css` だけで、`<script>` がない。
- `[NFR-005]` `index.html` に `<meta name="viewport" content="width=device-width, initial-scale=1">` がある。CSS に、720px を境にした切り替えがある。
- `[NFR-006]` `<html lang="ja">`、`<header>` `<nav aria-label>` `<main>` `<footer>` が 1 つずつ、`<h1>` が 1 つ、`<h2>` が 5 つある。CSS に `:focus-visible` の指定がある。
- `[NFR-007]` CSS の `:root` の変数を読み取り、相対輝度からコントラスト比を計算して、次の組がすべて 4.5:1 以上であることを確かめる: `--ink` / `--bg`、`--ink` / `--card`、`--muted` / `--bg`、`--muted` / `--card`、`--band-ink` / `--band`。
- `[NFR-008]` `site/lp/` に、参照元の固有名詞（会社名の `ジンザイベース`、ドメインの `jinzaibase`）を含まない。拒否リストには、電話番号・許認可番号・人名のような個人性の高い値は載せない（テストにも書かないため）。

### 手動（`npm run serve` で確認）
- **M-1** `http://localhost:5173/lp/index.html` を開くと、見出し領域と 5 つのセクション、フッターが、この順に表示される。内容がすべてダミーである。
- **M-2** 5 つのリンクを、マウスと Tab + Enter の両方で押すと、該当のセクションへ移動する。OS の「視差効果を減らす」を有効にすると、スムーズスクロールしない。
- **M-3** ブラウザの幅を 360px・768px・1440px にして、横スクロールが出ず、OUTLINE の一覧が崩れない（360px では、項目名の下に内容が縦に並ぶ）。
- **M-4** キーボードだけで、全リンクにフォーカスが移り、フォーカスの位置が、見出し領域の中でも、本文の中でも見える。
- **M-5** ブラウザのアクセシビリティツリー（または VoiceOver）で、ランドマークと見出し（`h1` → `h2`）が識別できる。
- **M-6** ページ全体を読み、実在の企業名・人名・住所・電話番号・許認可番号が含まれていない。

## リスクと未決事項
- **REQ-003 は Claude が起こした下書き（draft）。** 要件が変われば、本書も変わる。特に、内容を架空にする前提（NFR-008）を変えるなら、設計の方針から見直す。
- **`/lp/` で開けない。** `scripts/serve.mjs`（人間の領域）が、ディレクトリへのアクセスを `index.html` に対応づけていないため。人間への依頼事項: `serve.mjs` を直すか、README に `/lp/index.html` で開くと書く。
- **`site/AGENTS.md`（人間の領域）が ToDo 向けの記述になっている。** 「`todo.js` は純粋関数」などは `site/lp/` に関係しない。人間への依頼事項: `site/lp/` の追加ルール（JavaScript を使わない、外部 URL を使わない、文言はすべて架空）を足す。
- 静的テストは、見た目（レイアウトの崩れ、色の見え方）を保証しない。M-3 と M-4 は手動で確認する。
- 参照元のページは更新されうる。本書は、2026-11-25 時点の構成を参考にしている。
- 360px 未満の幅は、対象外。
